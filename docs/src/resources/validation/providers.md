# Provider rules

This page states the ModelProvider rules for fallback and budgets (rules 11, 12, 18, 32 to 34, and 41) and the credential rules for ModelProvider and ToolProvider (rules 49 and 50). [Validation and defaulting](../validation-and-defaulting.md) indexes every rule and says where each is enforced.

## Providers: fallback and budgets

These rules concern a single ModelProvider but run at reconcile time: rules 11, 12, and 41 must follow references to other providers, and rules 18 and 33 must match the gateway's model lookup and price parsing exactly ([ModelProviderReconciler](../../controller/reconcilers/modelprovider.md)).

**Rule 11: Fallback chains must terminate.** `ModelProvider.spec.fallback` chains must not be circular. *Reconcile time; `Ready=False, reason=FallbackIneligible`.* A chain is circular when a provider appears among its own ancestors; a provider reached through two different branches is not circular ([Fallback trees](../modelprovider.md#fallback-trees)).

**Rule 12: Fallback stays within formats the gateway can translate.** Each `spec.fallback[]` entry must have the same `spec.type` as the provider naming it, or a type the gateway translates to: `anthropic` and `openai` or `openai-compatible` may reference each other in either direction; `google-vertex` may reference only `google-vertex` and be referenced only by it. *Reconcile time, like rule 11; `Ready=False, reason=FallbackIneligible`. The gateway repeats the check per candidate.* See [Crossing formats](../../gateways/llm/fallback.md#crossing-formats).

**Rule 18: A budget degrade target must name a real model.** `budget.policies[].degradeTo` must match a model `id` in the same provider's `spec.models`. *Reconcile time; `Ready=False, reason=InvalidDegradeTarget`.* A missing target would fail routing the moment the threshold is crossed.

**Rule 32: Hard budget enforcement requires a block policy.** `budget.enforcement: hard` requires at least one `policies[]` entry with `action: block`. *CRD CEL on the budget block.* Hard mode's whole effect is to turn block thresholds into a guaranteed cap ([Hard enforcement](../../gateways/llm/budgets-and-rate-limits.md#hard-enforcement)); without a block policy it would be a silent no-op.

**Rule 33: Hard budget enforcement requires a fully priced catalog.** With `budget.enforcement: hard`, every model in `spec.models` must carry `costPer1MInputTokens` and `costPer1MOutputTokens` values the ledger can parse. *Reconcile time; `Ready=False, reason=HardBudgetUnpriced`, message naming the unpriced models.* An unpriced model costs zero in the ledger, so a cap over it is never reached.

**Rule 34: The boundary margin must sit strictly below every block threshold.** `budget.hard.boundaryMarginPercent` (0 to 100, default 5) must, for every `policies[]` entry with `action: block`, be strictly less than that policy's `atPercent`. *CRD CEL on the budget block.* A margin at or above a block threshold would start the boundary region at zero utilization and serialize all traffic from the first request.

**Rule 41: A model map must name real models on both ends.** In `spec.fallback[].modelMap`, every key must match a model `id` in this provider's `spec.models` and every value a model `id` in the referenced provider's. *Reconcile time; `Ready=False, reason=InvalidModelMap` on the provider carrying the map, naming the entry.* A map on a same-type edge is allowed and applied the same way ([Crossing formats](../../gateways/llm/fallback.md#crossing-formats)).

## Provider credentials

Rules 49 and 50 decide which Secret a provider may use and where its credential may go. Both run at reconcile time, never at apply time, and nothing is rejected at apply. The ModelProviderReconciler and ToolProviderReconciler check them, and the gateway checks them again on every credential read ([Credential handling](../../gateways/llm/provider-routing.md#credential-handling) for LLM calls, [Credential injection](../../gateways/tool-plane.md#credential-injection) for tool calls).

**Rule 49: A provider may use only Secrets that opted in.** Every Secret that a ModelProvider `spec.credentialsRef` names, or a ToolProvider `spec.credentialsRef` names when it is set, must carry the label `kaalm.io/provider-credential` with the exact value `"true"`. Other Kaalm labels do not count: the channel label of rule 45 covers channels, the workload label `kaalm.io/workload-secret` of rule 48 covers workloads, and each label covers one use. The label key is fixed and not configurable. *Reconcile time; `Ready=False, reason=SecretNotOptedIn` (the same reason as rule 45), and a `Warning` event with the same reason when the reason first appears on `Ready`.* The message names the Secret and the label, never a key. The label separates a credential meant for a provider from every other Secret in `kaalm-system`, such as `kaalm-gateway-session-key` or a cert-manager `*-tls` Secret. Whoever manages Secrets there sets it, and writing a provider does not ([Roles for people](../../security/rbac.md#persona-roles)).

**Rule 50: A provider credential goes only to hosts its Secret approves.** The same Secret must list the hostname of the provider's `spec.endpoint` in its `kaalm.io/provider-hosts` annotation: a comma-separated list of bare hostnames the credential manager approves. An entry must equal the endpoint hostname, as in rule 46: there are no wildcards such as `*.example.com`, and no parent-domain or suffix matches. The port, the path, and any userinfo in `spec.endpoint` play no part, and the host checked is the host dialed. List an IP literal or IPv6 address bare, such as `10.0.0.5` or `fd00::1`. Only `kaalm.io/provider-hosts` counts; `kaalm.io/callback-hosts` does not. *Reconcile time; `Ready=False, reason=EndpointHostNotApproved`, and a `Warning` event with the same reason when the reason first appears on `Ready`.* A `spec.endpoint` with no parsable hostname, such as `https://`, reports the same reason, because no host exists for the Secret to approve. The rule applies to every ModelProvider type (`anthropic`, `openai`, `openai-compatible`, and `google-vertex`) and to a ToolProvider with `credentialsRef`. A ToolProvider without `credentialsRef` reads no Secret, so the rule does not apply to it. For `google-vertex`, the rule checks the `spec.endpoint` host because that is where the minted access token goes. The JWT assertion goes to the key's `token_uri`, which lives inside the Secret that only the credential manager writes, and the rule does not check it.

The controller reads the Secret, then checks rule 49, then rule 50, then the key; the first failure decides the reason (`CredentialsMissing`, `SecretNotOptedIn`, `EndpointHostNotApproved`, or `CredentialsMissing` for a missing or empty key). A Secret that is unlabeled or does not approve the host reports only that, even when its key is also missing, so status says nothing about the keys of a Secret that has not been approved.

A rule 49 or 50 failure ends the reconcile pass at the credential step, before configuration validation, the budget fold, the gateway mirror, and the health probe. A probe therefore never sends a credential to an unapproved host, and it needs no check of its own. `Healthy` keeps its last value on such a pass, as it does under `CredentialsMissing`. Adding, changing, or removing the label or the annotation re-evaluates the provider without a spec change. Editing `spec.endpoint` to an unlisted host makes the provider `Ready=False, reason=EndpointHostNotApproved` on that pass, before any probe reaches the new host, so annotate the Secret first.

The gateway applies the same checks on every credential read. How a refusal reaches a caller is specified under the two pages linked above.
