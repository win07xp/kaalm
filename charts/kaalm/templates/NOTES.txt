Kaalm {{ .Chart.AppVersion }} installed into namespace {{ .Release.Namespace }}.

The chart installs:
  - the 6 CustomResourceDefinitions
  - the controller and gateway Deployments (2 replicas each, PDB minAvailable 1),
    and the console Deployment when console.enabled is set
  - ServiceAccounts, ClusterRoles/Bindings, and the gateway's namespaced Role
  - the cert-manager trust chain (kaalm-selfsigned + kaalm-ca-issuer
    ClusterIssuers, the kaalm-ca root Certificate, the gateway and controller
    leaf Certificates) and the trust-manager kaalm-ca and kaalm-ca-system
    Bundles
  - a default "standard" AgentClass, which allows storage and hibernation
{{- if and .Values.standardAgentClass.enabled (not .Values.standardAgentClass.allowedProviders) }}

The "standard" AgentClass allows no ModelProvider, so an Agent that names one
goes Degraded with ClassConstraintViolation. Create a ModelProvider (see
"Providing LLM access":
https://github.com/win07xp/kaalm/blob/v{{ .Chart.Version }}/guide/src/platform/llm-access.md),
then name it:
  helm upgrade {{ .Release.Name }} oci://ghcr.io/win07xp/charts/kaalm --version {{ .Chart.Version }} \
    -n {{ .Release.Namespace }} --reuse-values \
    --set standardAgentClass.allowedProviders={YOUR-PROVIDER-NAME}
{{- end }}

Prerequisites (the chart does NOT install these):
  1. cert-manager, running with --enable-certificate-owner-ref=true
  2. trust-manager, with --trust-namespace matching
     certManager.clusterResourceNamespace (default "cert-manager")
  3. a CNI that enforces NetworkPolicy: the agent NetworkPolicies Kaalm
     creates have no effect without one

Check the rollout:
  kubectl -n {{ .Release.Namespace }} rollout status deploy/kaalm-controller
  kubectl -n {{ .Release.Namespace }} rollout status deploy/kaalm-gateway

The Deployments mount cert-manager-issued Secrets and the trust-manager CA
ConfigMap; on first install the Pods stay ContainerCreating until those issue.
If they never become Ready, verify the kaalm-ca-issuer ClusterIssuer is
Ready and that certManager.clusterResourceNamespace matches your cert-manager
and trust-manager configuration.

CRD upgrades are never applied by `helm upgrade`. Before upgrading, pull the
chart version you are upgrading to and apply its crds/ directory:
  helm pull oci://ghcr.io/win07xp/charts/kaalm --version NEW_VERSION --untar
  kubectl apply --server-side --force-conflicts -f kaalm/crds/
The upgrading page has the full steps:
https://github.com/win07xp/kaalm/blob/v{{ .Chart.Version }}/guide/src/getting-started/upgrading.md
