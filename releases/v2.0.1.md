Kaalm 2.0.1 is a patch release on 2.0.0. The upgrade is in place: apply the CRDs, then run `helm upgrade`, as [Upgrading Kaalm](https://github.com/win07xp/kaalm/blob/v2.0.1/guide/src/getting-started/upgrading.md) describes. No API, CRD schema, or chart value changes. Agent Pods get the new startup probe the next time they are created or woken, because the upgrade does not restart running Pods.

Published artifacts, all at version `2.0.1`:

- Images: `ghcr.io/win07xp/kaalm-controller`, `kaalm-gateway`, `kaalm-console`, `kaalm-agent-python`, and `kaalm-agent-go`. The `latest` tag moves to `2.0.1`.
- Chart: `oci://ghcr.io/win07xp/charts/kaalm`.
- Go runtime module: `github.com/win07xp/kaalm/agentruntime/v2`, tagged `agentruntime/v2.0.1`.

## Fixes

- **Messages survive a Pod replacement.** A message sent while an Agent's Pod is being replaced or is resuming is held until the Pod is reachable, instead of being lost. This covers a replacement after a class edit and one after an eviction, a node drain, a deletion by hand, or a terminal Pod ([#562](https://github.com/win07xp/kaalm/issues/562), [#563](https://github.com/win07xp/kaalm/issues/563)).
- **A disrupted Agent shows `PodDisrupted`.** While an involuntary replacement runs, the Agent's `PodUpToDate` condition is `False` with the reason `PodDisrupted`. The new Pod gets a full `idleTimeout` from the moment it is Ready, so the Agent does not hibernate before the held message arrives. See [Agent status](https://github.com/win07xp/kaalm/blob/v2.0.1/docs/src/resources/agent.md#status) ([#563](https://github.com/win07xp/kaalm/issues/563)).
- **A message that arrives as an Agent starts hibernating wakes it.** The gateway requests one wake, so the message does not wait out `wakeTimeout` and fail ([#564](https://github.com/win07xp/kaalm/issues/564)).
- **A recreated Agent starts clean.** An Agent deleted and recreated under the same name no longer inherits the old Agent's activity, so it does not idle or hibernate right after its first start ([#574](https://github.com/win07xp/kaalm/issues/574)).
- **Woken agents are reachable sooner.** Agent Pods have a startup probe on `/livez` (every second, up to 30 failures), so an agent that is not listening at the first check does not wait 10 seconds for the next readiness check. The gateway checks a woken agent every 250 ms for the first 5 seconds, then every 2 seconds. A wake of the Python base image drops from about 12 seconds to about 3 seconds. See [the startup probe](https://github.com/win07xp/kaalm/blob/v2.0.1/docs/src/controller/reconcilers/agent.md) ([#555](https://github.com/win07xp/kaalm/issues/555)).

## Smaller changes

- The chart's install notes give commands that work for an OCI install. They link [Providing LLM access](https://github.com/win07xp/kaalm/blob/v2.0.1/guide/src/platform/llm-access.md) at the chart's version, show a `helm upgrade` command on the OCI chart that sets `standardAgentClass.allowedProviders`, and tell you to `helm pull` the new chart version and apply its `crds/` directory for a CRD upgrade.
- The gateway strips the `X-Goog-Api-Key` header from agent requests, so an agent's own key never reaches Google next to the injected credential.
- One trailing slash on a channel platform base URL is ignored.
- Channel health keeps a channel's newest success apart from its failures, so a flood of failed requests cannot push the success out of the report.
- A long rejection text in an AgentTask's provisioning deadline message is cut once, so the retry Warning keeps its attempt count (`retrying (n/m)`).
- The gateway reads spend with one labeled list per tick instead of one read per provider, which removes most of its steady API traffic. Budget and agent-spend ConfigMaps carry the label `kaalm.io/spend` ([#528](https://github.com/win07xp/kaalm/issues/528)).

## Publishing

Releases are published by merging a release PR, as [Releasing Kaalm](https://github.com/win07xp/kaalm/blob/v2.0.1/RELEASING.md) describes. The release PR runs the upgrade e2e from the previous release, and the release is tagged and published only after that check passed on the PR's head commit. This is the first release published that way ([#557](https://github.com/win07xp/kaalm/issues/557), [#579](https://github.com/win07xp/kaalm/issues/579)).
