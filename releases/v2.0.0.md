Kaalm 2.0.0 is the first stable release. Kaalm runs AI agents as a Kubernetes workload: you declare an Agent or an AgentTask, and the operator runs it with its own identity, network policy, model gateway, spend budget, and tool access. You can run agents in microVMs, limit which teams can use a class, and roll out class changes safely.

2.0.0 installs fresh. There is no upgrade from 1.x or 0.x. From 2.0.0 on, an upgrade within 2.x keeps your manifests working, and a breaking change arrives as a new API version with conversion. See [API versioning and deprecation](https://github.com/win07xp/kaalm/blob/v2.0.0/docs/src/operations/api-versioning.md).

## Install

The chart needs Kubernetes 1.35 or later, cert-manager, trust-manager, and a CNI that enforces NetworkPolicy. The [installation page](https://github.com/win07xp/kaalm/blob/v2.0.0/guide/src/getting-started/installation.md) has the commands.

To move from 1.x or 0.x, you remove Kaalm completely and install 2.0.0.

**Removing Kaalm deletes every Kaalm resource in the cluster, and each agent's PVC and its data, unless the agent's class sets `persistence.pvcRetention: Retain` (the default is `Delete`).**

If you run 0.x, upgrade to 1.0.0 first, because 0.5.0 and earlier serve only `v1alpha1`.

Then follow every step in [Moving from 1.x or 0.x](https://github.com/win07xp/kaalm/blob/v2.0.0/guide/src/getting-started/upgrading.md#moving-from-1x-or-0x). The steps cover keeping the PVCs, backing up your manifests without the chart's `standard` class, removing `allowHostNetwork` and the removed controller values, labeling and annotating your credential Secrets, and reapplying and checking that everything is `Ready`.

Published artifacts, all at version `2.0.0`:

- Images: `ghcr.io/win07xp/kaalm-controller`, `kaalm-gateway`, `kaalm-console`, `kaalm-agent-python`, and `kaalm-agent-go`.
- Chart: `oci://ghcr.io/win07xp/charts/kaalm`.
- Go runtime module: `github.com/win07xp/kaalm/agentruntime/v2`, tagged `agentruntime/v2.0.0`. Go agents import the `/v2` path, and the module needs Go 1.26.0 or later.
- Python agents: the `kaalm-agent-python` base image uses Python 3.14.

## What's new

### Isolation and access

- **Agents in microVMs.** An AgentClass names a `RuntimeClass` such as Kata, and each agent Pod runs in its own virtual machine with its own kernel. The guide chapter [Running agents in microVMs](https://github.com/win07xp/kaalm/blob/v2.0.0/guide/src/platform/microvms.md) covers node prerequisites, installing Kata, and VM sizing ([#168](https://github.com/win07xp/kaalm/issues/168)).
- **Restrict a class to chosen teams.** `AgentClass.spec.allowedNamespaces` takes namespace glob patterns. The chart value is `standardAgentClass.allowedNamespaces`. A namespace that the class does not admit gets `NamespaceNotAllowed` ([#340](https://github.com/win07xp/kaalm/issues/340), [#371](https://github.com/win07xp/kaalm/issues/371)).
- **Secrets are opt-in.** A channel, workload, or provider uses only Secrets you label for that use: `kaalm.io/channel-credential`, `kaalm.io/workload-secret`, or `kaalm.io/provider-credential`, each set to `"true"`. A channel callback token and a provider credential also name the hosts they may go to, in the annotations `kaalm.io/callback-hosts` and `kaalm.io/provider-hosts`. An unlabeled Secret holds the object at `Ready=False` with the reason `SecretNotOptedIn` ([#350](https://github.com/win07xp/kaalm/issues/350), [#355](https://github.com/win07xp/kaalm/issues/355), [#356](https://github.com/win07xp/kaalm/issues/356)).
- **Persona roles in the chart.** `rbac.personas` creates the `kaalm-platform-admin`, `kaalm-catalog-reader`, `kaalm-developer`, and `kaalm-secrets-admin` ClusterRoles and binds them to the users and groups you list. All of it is off by default ([#244](https://github.com/win07xp/kaalm/issues/244)).

### Lifecycle

- **Safe class rollouts.** An edit to an AgentClass reaches running Pods, idle Agents first, at the pace `lifecycle.maxUnavailableOnDrift` sets (default `25%`). The rollout halts if replacement Pods crash-loop. `kubectl get agentclass` shows a `Replacing` column ([#210](https://github.com/win07xp/kaalm/issues/210), [#295](https://github.com/win07xp/kaalm/issues/295)).
- **Task bounds on a class.** `defaultTaskTimeout`, `maxTaskTimeout`, `defaultTTLSecondsAfterFinished`, and `maxTTLSecondsAfterFinished` set the default and the cap for AgentTasks. The chart's `standard` class sets a one-hour `defaultTaskTimeout` ([#239](https://github.com/win07xp/kaalm/issues/239)).
- **Visible create failures.** A rejected Pod or child create shows as `PodCreateRejected` or `ChildWriteRejected`. A task attempt with no Ready Pod after 5 minutes fails with `ProvisioningDeadlineExceeded`, and the task retries up to `backoffLimit` before it fails ([#369](https://github.com/win07xp/kaalm/issues/369), [#407](https://github.com/win07xp/kaalm/issues/407)).
- **Self-healing tasks.** A running AgentTask re-creates a deleted child and reverts edits to its NetworkPolicies and completion RBAC ([#445](https://github.com/win07xp/kaalm/issues/445), [#452](https://github.com/win07xp/kaalm/issues/452)).
- **Python tasks.** The Python base image supports task mode with `async def run_task()`, `kaalm.complete_task()`, and `KAALM_TASK_AUTOCOMPLETE` ([#235](https://github.com/win07xp/kaalm/issues/235)).

### Gateway and channels

- **Rate limits and streaming.** `ModelProvider.spec.rateLimits.tokensPerMinute` is enforced, and a limited call gets `429 rate_limited` with a `Retry-After` computed from the refill time. Long LLM streams run to completion, because `gateway.providerFirstByteTimeout` bounds the wait for the first byte and for inactivity, not the whole call. A truncated stream ends with one error event, so it no longer looks complete ([#201](https://github.com/win07xp/kaalm/issues/201), [#202](https://github.com/win07xp/kaalm/issues/202), [#288](https://github.com/win07xp/kaalm/issues/288)).
- **MCP limits.** Tool calls have their own body cap and timeout: `gateway.mcpMaxBodyBytes` and `gateway.mcpUpstreamTimeout` ([#203](https://github.com/win07xp/kaalm/issues/203)).
- **Graceful restarts.** After SIGTERM, the gateway and console keep serving for `drainDelay` (default 5 seconds), then finish in-flight requests within `timeout` (default 30 seconds), so the gateway drains before it stops. The values are `gateway.shutdown.*` and `console.shutdown.*` ([#479](https://github.com/win07xp/kaalm/issues/479)).
- **Channels react to Secret changes.** A channel re-runs as soon as a Secret it references changes. The async response window follows the agent's `wakeTimeout` instead of a fixed 10 minutes ([#205](https://github.com/win07xp/kaalm/issues/205), [#357](https://github.com/win07xp/kaalm/issues/357)).
- **Provider health.** `google-vertex` providers get a liveness probe, failing probes back off, and the controller reports `FallbackIneligible` when a provider's fallback cannot take over ([#214](https://github.com/win07xp/kaalm/issues/214)).

### Observability

- Events carry an action and, where it applies, a related object, and they use the `events.k8s.io/v1` API. `PhaseChanged` fires on every Agent phase change, and every `Ready=False` reason raises a Warning event ([#213](https://github.com/win07xp/kaalm/issues/213), [#502](https://github.com/win07xp/kaalm/issues/502)).
- An LLM stream that the provider breaks counts as `error`, and an LLM or MCP stream that the caller abandons counts as `client_closed`, in `kaalm_llm_requests_total` and `kaalm_tool_calls_total`. Neither counts as `ok` ([#455](https://github.com/win07xp/kaalm/issues/455), [#444](https://github.com/win07xp/kaalm/issues/444)).
- `kaalm_llm_usage_missing_total` counts LLM responses that report no token usage, and the provider dashboard has a panel for it ([#201](https://github.com/win07xp/kaalm/issues/201)).

### Console

- The console caps chat bodies, takes `?limit=` on list routes (default 100, maximum 1,000), answers every `/api/` path with a JSON error envelope, and reuses its gateway connections ([#224](https://github.com/win07xp/kaalm/issues/224), [#427](https://github.com/win07xp/kaalm/issues/427), [#486](https://github.com/win07xp/kaalm/issues/486)).

## Significant fixes

- A workload could read any Secret in its namespace through `spec.env`, and a provider could name any Secret in the operator namespace ([#355](https://github.com/win07xp/kaalm/issues/355), [#356](https://github.com/win07xp/kaalm/issues/356)).
- An agent could call a tool it was not granted, or a denied MCP method, by repeating `name` or `method` in the JSON-RPC body or varying its case ([#512](https://github.com/win07xp/kaalm/issues/512)).
- `tools/list` narrowing could show an agent the names of tools it was not granted. Calls to them stayed refused ([#547](https://github.com/win07xp/kaalm/issues/547)).
- An agent could send its own `stream_options` without `include_usage` on an OpenAI-format stream. The call then settled at zero spend and got past hard budgets and `tokensPerMinute` ([#514](https://github.com/win07xp/kaalm/issues/514)).
- A workload's TLS Secret name was predictable, so another tenant could pre-create it. The name now ends with part of the workload's UID ([#360](https://github.com/win07xp/kaalm/issues/360)).
- A completion message near the 32 KiB limit could leave a task stuck in `Completing`. The status now holds the first 4,096 bytes, and the full message stays in the task's `<task>-completion` ConfigMap ([#505](https://github.com/win07xp/kaalm/pull/505)).
- A ModelProvider, ToolProvider, or AgentClass deleted right after a new referrer was created could be removed while still referenced ([#526](https://github.com/win07xp/kaalm/issues/526)).
- Long text in a condition message (webhook denials, tool server errors, provider or spec names) pushed status writes past the size limit. Every status write then failed, and Ready or Healthy kept a stale value. For example, a ToolProvider stayed Healthy while its server was down ([#516](https://github.com/win07xp/kaalm/issues/516), [#520](https://github.com/win07xp/kaalm/issues/520), [#524](https://github.com/win07xp/kaalm/issues/524), [#527](https://github.com/win07xp/kaalm/issues/527), [#529](https://github.com/win07xp/kaalm/issues/529), [#535](https://github.com/win07xp/kaalm/issues/535), [#538](https://github.com/win07xp/kaalm/issues/538)).
- LLM streams were cut at 120 seconds ([#201](https://github.com/win07xp/kaalm/issues/201)).
- AgentClass security, runtime, and pull edits never reached running Pods, and a changed Pod spec restarted a whole class at once ([#210](https://github.com/win07xp/kaalm/issues/210), [#295](https://github.com/win07xp/kaalm/issues/295)).
- An Agent Pod could keep mounting a stale TLS Secret and fail at certificate expiry ([#384](https://github.com/win07xp/kaalm/issues/384)).
- A `requestsPerMinute` below the gateway replica count refused every call ([#345](https://github.com/win07xp/kaalm/issues/345)).
- A recreated ModelProvider inherited the old spend and its blocked namespaces ([#457](https://github.com/win07xp/kaalm/issues/457)).
- The agent runtimes answered `/readyz` with `200` before they were ready ([#234](https://github.com/win07xp/kaalm/issues/234)).
- The class reported FQDN egress as supported on any Calico cluster, but only Cilium enforces it ([#273](https://github.com/win07xp/kaalm/issues/273)).

The full list is on the [v2.0.0 milestone](https://github.com/win07xp/kaalm/milestone/8?closed=1).

## Removed

- **The `v1alpha1` API and the conversion webhook.** `kaalm.io/v1beta1` is the only version. Write manifests against `v1beta1`. The controller no longer listens on port 9444.
- **`AgentClass.spec.network.allowHostNetwork`.** It never had an effect. Delete the field from your classes.
- **The chart values `controller.probeCA` and `controller.trustClusterCAForProbes`.** A values file that sets either key fails the render with a message that names the replacement, even when the value is `false` or empty. 1.0.0 set both by default, so values you saved with `helm get values --all` from 1.x need both removed. Set `gateway.upstreamCA` or `gateway.trustClusterCAForUpstream`, which provider health probes also trust.

## Known limits

- The `agentSandbox` runtime backend does not ship. Use a RuntimeClass such as Kata or gVisor for isolation ([#167](https://github.com/win07xp/kaalm/issues/167)).
- The chart has no `values.schema.json`, so a typo in a value is not caught when Helm renders ([#351](https://github.com/win07xp/kaalm/issues/351)).
- The agent runtimes rewrite their whole state file on every message ([#484](https://github.com/win07xp/kaalm/issues/484)).
- The Secret watcher runs one watch per Secret in each process, so a fleet with hundreds of channel Secrets holds many watch streams ([#485](https://github.com/win07xp/kaalm/issues/485)).
- Agents and AgentTasks pick up a labeled Secret on a 30-second re-check, not at once ([#406](https://github.com/win07xp/kaalm/issues/406)).
- The gateway does not serve `google-vertex` providers. They get a liveness probe only.
- The MCP broker serves tools only ([#80](https://github.com/win07xp/kaalm/issues/80)). Discord supports slash commands over HTTP only ([#124](https://github.com/win07xp/kaalm/issues/124)).
- `allowedHosts` is enforced on Cilium only. On other CNIs the class reports `FQDNPolicySupported=False` and the traffic stays blocked.
- `tokensPerMinute` is approximate across gateway replicas, and concurrent streams can overshoot it.
- An Agent and an AgentTask cannot share a name in one namespace.
- A rolling restart of the gateway can still fail a few requests ([#554](https://github.com/win07xp/kaalm/issues/554)).
- A Python agent waits up to about 10 extra seconds on each wake, because the readiness probe uses the default 10-second period ([#555](https://github.com/win07xp/kaalm/issues/555)).
- A Secret deleted within about one round trip of a watch opening can stay cached, so the gateway keeps serving it and the controller does not re-run the channel that references it ([#551](https://github.com/win07xp/kaalm/issues/551)).

Open follow-ups are on the [v2.1.0 milestone](https://github.com/win07xp/kaalm/milestone/9) and the issue tracker.
