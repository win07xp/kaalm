Kaalm 2.2.0 is a minor release on 2.1.0. It serves `google-vertex` ModelProviders, reserves tokens at admission under `tokensPerMinute`, charges an estimate for stream usage the provider did not report, relays non-streamed LLM answers as they arrive, and adds `kaalm.langchain_chat_anthropic()` to the Python base image. The upgrade is in place: apply the CRDs, then run `helm upgrade`, as [Upgrading Kaalm](https://github.com/win07xp/kaalm/blob/v2.2.0/guide/src/getting-started/upgrading.md) describes. The API does not change. The ModelProvider CRD changes only in the description of `maxOutputTokens`, so nothing validates differently.

Three changes can alter what your callers see after the upgrade:

- **A provider with `tokensPerMinute` needs `maxOutputTokens` on its models.** The gateway now reserves a call's tokens when it admits the call. A request with no output cap of its own on a model with no `maxOutputTokens` reserves a whole replica share, which is `tokensPerMinute` divided by the number of gateway replicas. Such calls run about one at a time for each namespace and model on each replica, and other callers get `429 rate_limited` with a `Retry-After` of up to about a minute. A larger `tokensPerMinute` does not help, because the reservation grows with it. Before you upgrade, set `maxOutputTokens` on every model of each provider that sets `tokensPerMinute`, or have your agents send `max_tokens`. After the upgrade, the provider's `MaxOutputTokensUnset` condition names the models that still lack it. See [Rate limits](https://github.com/win07xp/kaalm/blob/v2.2.0/guide/src/platform/budgets-limits-fallback.md#rate-limits).
- **Callers must use the path for the provider's type.** A request whose path format is not the primary provider's type gets `400 invalid_request`, for example `/v1/chat/completions` to an `anthropic` provider. Before, the gateway translated such a request, which the design book never promised. See the first entry under Changes.
- **Streams that end without full usage cost something.** A 2xx stream that ends without complete provider usage is charged an estimate instead of zero, so budgets can run out sooner for callers that abandon streams. See the first entry under Fixes.

Published artifacts, all at version `2.2.0`:

- Images: `ghcr.io/win07xp/kaalm-controller`, `kaalm-gateway`, `kaalm-console`, `kaalm-agent-python`, and `kaalm-agent-go`. The `latest` tag moves to `2.2.0`.
- Chart: `oci://ghcr.io/win07xp/charts/kaalm`.
- Go runtime module: `github.com/win07xp/kaalm/agentruntime/v2`, tagged `agentruntime/v2.2.0`.

## Gemini models through Vertex

A `google-vertex` ModelProvider serves Google's Gemini models in Google's native format. Before, the gateway refused a request that named one. If you already have a `google-vertex` provider, it serves requests once the gateway rolls out ([#559](https://github.com/win07xp/kaalm/issues/559)).

An agent calls `:generateContent` or `:streamGenerateContent` on the gateway, under `/v1/projects/...` or `/v1beta1/projects/...`, with the model qualified by the provider name, such as `vertex-shared/gemini-2.5-flash`. With the `google-genai` SDK, set `vertexai=True`, point the HTTP options' `base_url` at `$KAALM_GATEWAY_ENDPOINT`, and pass the qualified model name. A project, location, provider, or model segment that is `.` or `..`, including a percent-encoded one such as `%2e%2e`, is not a Vertex path, and the gateway rejects the request. The gateway copies the project and location into the upstream URL, so a dot segment would let a proxy or upstream that resolves it serve a path the gateway never accepted. Nothing reaches Google or the token endpoint ([#640](https://github.com/win07xp/kaalm/issues/640)). See [Request format detection](https://github.com/win07xp/kaalm/blob/v2.2.0/docs/src/gateways/llm/request-handling.md#request-format-detection).

The provider's Secret holds a service-account JSON key. The gateway exchanges it for short-lived access tokens, so the key never reaches an agent. A token that Google refuses with `401` is dropped, and the next request mints a new one ([#618](https://github.com/win07xp/kaalm/issues/618)). Budgets, rate limits, hard enforcement, tracing, and metrics apply as for the other provider types, and Gemini thinking tokens count as output tokens. A fallback for a `google-vertex` provider must be another `google-vertex` provider. Claude models on Vertex and workload-identity credentials are not served.

See [Serve Gemini models through Vertex](https://github.com/win07xp/kaalm/blob/v2.2.0/guide/src/platform/llm-access.md#5-serve-gemini-models-through-vertex) for the Secret, the provider, and the SDK settings, and [Vertex access tokens](https://github.com/win07xp/kaalm/blob/v2.2.0/docs/src/gateways/llm/provider-routing.md#vertex-access-tokens) for the token mint.

## Changes

- **A request must use the path for the provider's type.** The gateway answers `400 invalid_request` when the request path's format is not the primary provider type's format. `/v1/messages` is the path for an `anthropic` provider. `/v1/chat/completions` and `/v1/completions` are the paths for `openai` and `openai-compatible` providers, which share one format. A `google-vertex` provider takes only a Vertex path, and a Vertex path to any other type is rejected. The message names the provider's type and the path to call. The check runs after route authorization, so a caller never learns the type of a provider it may not use, and before budget admission and the rate limit, so a rejected request takes no slot, reservation, or spend. Fallback translation is unchanged: a fallback candidate of another format still gets a translated request. If your agent sent an Anthropic-format request to an OpenAI provider, or the reverse, point it at a provider of its format or change its path. The Python starter's README example used `/v1/chat/completions` with an Anthropic model and now uses `/v1/messages`. The Go starter's `ask` feature posts to `/v1/chat/completions`, so its `KAALM_STARTER_MODEL` must name a model on an `openai` or `openai-compatible` provider. See [Request handling](https://github.com/win07xp/kaalm/blob/v2.2.0/docs/src/gateways/llm/request-handling.md#request-flow) ([#629](https://github.com/win07xp/kaalm/issues/629)).
- **The gateway drops every `x-goog-` header a caller sends.** The match ignores letter case and applies to every provider type. Google APIs read these headers as controls on the call: the project billed (`x-goog-user-project`), alternate credentials, routing, and a field mask that can remove `usageMetadata`, so the call would settle at zero spend. With the provider's credential, those choices belong to the provider. `x-goog-api-key` was already stripped as authentication material. If an agent sent `x-goog-user-project`, `x-goog-api-client`, or another header with this prefix through the gateway, the upstream no longer receives it. Anthropic and OpenAI do not read these headers, so the drop matters most for a Google endpoint, such as a `google-vertex` provider or an `openai-compatible` endpoint that Google hosts. See [The forwarded-header contract](https://github.com/win07xp/kaalm/blob/v2.2.0/docs/src/gateways/llm/request-handling.md#the-forwarded-header-contract) ([#640](https://github.com/win07xp/kaalm/issues/640)).
- **Tokens are reserved at admission under `tokensPerMinute`.** The gateway used to debit tokens only after a call finished, so concurrent long calls all passed admission and a burst could go far over the limit. Now the gateway takes a reservation from the token bucket when it admits a call, and settles it when the call ends. The reservation is an input estimate (the body's bytes divided by 4, less base64 images, audio, and video) plus an output cap: the request's own cap, lowered to the model's `maxOutputTokens` when that is smaller; else the model's `maxOutputTokens`; else a whole replica share. The bucket still admits while it is above 0, so a large cap is never refused outright. When the call ends, the usage the provider reports replaces the reservation. A 2xx that did not finish cleanly is charged at least the reservation, and a call that no provider serves gets it back. PDF and text documents count at their size, so leave room for them in `tokensPerMinute`. Images, audio, and video count only when the call settles, so concurrent calls that carry them can overshoot the limit by what the provider bills for them. `Retry-After` is now a worst case, because a call that settles below its reservation frees the bucket sooner. The `MaxOutputTokensUnset` condition and its `Warning` event also fire when a provider sets `tokensPerMinute` and a model declares no `maxOutputTokens`. See [The token limit](https://github.com/win07xp/kaalm/blob/v2.2.0/docs/src/gateways/llm/budgets-and-rate-limits.md#the-token-limit) ([#560](https://github.com/win07xp/kaalm/issues/560), [#628](https://github.com/win07xp/kaalm/issues/628)).
- **The Python base image has an eighth handler ABI member, `kaalm.langchain_chat_anthropic(**kwargs)`.** It returns a LangChain `ChatAnthropic` whose sync and async clients carry the Pod's identity and follow certificate rotation, so `invoke` and `ainvoke` both work and the rest of your graph is unchanged. `base_url` defaults to the gateway endpoint and `api_key` to the placeholder `managed-by-kaalm`. Any other argument passes through to `ChatAnthropic`. `anthropic_proxy` raises `TypeError`, because a proxy would route around the Pod's identity. The image does not bundle LangChain: install `langchain-anthropic` in your `FROM` build, or the call raises `ImportError`. It is tested against `langchain-anthropic` 1.7.12, and a release that no longer builds its clients the way the factory expects raises `RuntimeError` instead of returning a model without the Pod's identity. Existing handlers are unaffected. See [Use ChatAnthropic on the base image](https://github.com/win07xp/kaalm/blob/v2.2.0/guide/src/developers/framework-agents.md#use-chatanthropic-on-the-base-image) ([#635](https://github.com/win07xp/kaalm/issues/635)).
- **The agent skill installs with the `skills` CLI.** For a coding agent other than Claude Code, run `npx skills add win07xp/kaalm@v2.2.0`, which needs Node.js. The CLI installs the skill into the agents it finds on your machine, and the skill is listed at [skills.sh](https://skills.sh/win07xp/kaalm). The Claude Code plugin commands are unchanged. The skill also has a guide page, [Using the agent skill](https://github.com/win07xp/kaalm/blob/v2.2.0/guide/src/getting-started/agent-skill.md), and a chapter in the learn book, [Let a coding agent help](https://github.com/win07xp/kaalm/blob/v2.2.0/learn/src/let-a-coding-agent-help.md) ([#615](https://github.com/win07xp/kaalm/issues/615)).

## Fixes

- **A stream that ends without complete usage is charged an estimate.** This covers a caller that leaves early, a provider that breaks the stream or lets it go idle, and a provider that finishes cleanly but sends no usage. The gateway takes the usage the provider reported and estimates the missing input or output at about four bytes per token. The input estimate leaves out images, audio, and video, and counts a document's bytes. Before, such a stream settled at zero or at part of its real cost, and the budget never saw those tokens. The estimate counts toward the budget, the spend ledger, and `kaalm_llm_spend_usd_total`. The new counter `kaalm_llm_spend_estimated_usd_total`, with the `provider` and `namespace` labels, counts the estimated share, and the `kaalm-provider.json` Grafana dashboard has a panel for it, so re-import that file to get the panel. No CRD changes and no upgrade step is needed. See [Estimated usage](https://github.com/win07xp/kaalm/blob/v2.2.0/docs/src/gateways/llm/request-handling.md#streaming-responses) ([#621](https://github.com/win07xp/kaalm/issues/621)).
- **The gateway relays non-streamed answers as they arrive.** It used to read a whole non-streamed answer into memory before it wrote the first byte, so memory per request grew with the answer and the agent got nothing until the answer was complete. Now the gateway writes a 2xx answer as its bytes arrive and reads the token usage from the same bytes. Memory per request stays constant, spend settles after the last byte, and no size cap applies to a 2xx answer, because the provider has already billed it. An answer the provider cuts off reaches the agent cut off, and the gateway does not fall back once a 2xx has started. A caller that leaves does not avoid the charge: the gateway reads the answer to its end and settles its usage. An answer from a fallback candidate of another format is still held whole, because translation needs all of it, up to a bound of 1 MiB plus 16 bytes for each `max_tokens` of the translated request. A larger answer ends with `502 provider_error`. See [Response relay](https://github.com/win07xp/kaalm/blob/v2.2.0/docs/src/gateways/llm/request-handling.md#request-flow) ([#568](https://github.com/win07xp/kaalm/issues/568)).
- **The Python base image's HTTPS listener follows certificate rotation.** The listener kept the certificate and CA it loaded at startup. After a rotation it still presented the old certificate and trusted the old CA, so a Pod that ran past its certificate's lifetime without a restart (90 days by default) failed every gateway delivery at the TLS handshake while `/readyz` stayed `200`. Now each new handshake uses the current certificate and CA with no restart, and an open connection finishes on the material it started with. The listener also resumes no TLS session: it issues no session tickets and fails a resumed handshake, so a client cannot skip the check against a new CA with a session saved before the rotation. The Go runtime was not affected. See [Certificate reload on rotation](https://github.com/win07xp/kaalm/blob/v2.2.0/docs/src/runtime/contract.md#certificate-reload-on-rotation) ([#639](https://github.com/win07xp/kaalm/issues/639)).
- **Response headers that arrive after the first-byte timeout count as the timeout.** When a provider sends no response headers within `gateway.providerFirstByteTimeout`, the gateway cancels the attempt. A provider could answer the cancel by finishing its response, and its headers could reach the gateway before the connection closed. The gateway then relayed them as an answer: the caller got the provider's status with an empty body, the call settled at zero spend, and fallback did not run. Now the walk falls back, or the caller gets `504 provider_timeout`. See [Fallback triggers](https://github.com/win07xp/kaalm/blob/v2.2.0/docs/src/gateways/llm/fallback.md#fallback-triggers).

## Smaller changes

- The gateway's Pod wait counts only a Pod the Agent controls, meaning one with the Agent's labels and a controller owner reference of kind Agent. The controller sets both on every Pod it creates, so no upgrade step is needed. A Pod that only copies an Agent's labels no longer starts connects or ends a wait. See [Waiting for a Pod that is not reachable yet](https://github.com/win07xp/kaalm/blob/v2.2.0/docs/src/gateways/user/activation-and-activity.md#waiting-for-a-pod-that-is-not-reachable-yet).
- The chart's values schema rejects `gateway.maxPodWaitsPerAgent` below `1` at `helm install`, `helm upgrade`, and `helm template`. Before, `0` or a negative value made the gateway exit at startup.
- The controller's `google-vertex` probe reuses its access token until five minutes before the token expires, so the token endpoint sees about one mint per hour per provider, not one per probe. A rotated key takes effect on the next probe. See [The google-vertex probe](https://github.com/win07xp/kaalm/blob/v2.2.0/docs/src/controller/reconcilers/modelprovider.md#the-google-vertex-probe).
- The gateway does not forward a query string a caller sends on an LLM path to the provider. Request handling now says so. For a Vertex stream, the gateway sets `alt=sse` itself.
- The guide's Level 1 section shows how to keep the gateway token fresh with LangChain's `ChatAnthropic` in a Deployment outside Kaalm. `ChatAnthropic` takes neither `http_client` nor `http_async_client`, so the `httpx` auth hook cannot reach it. See [Running framework agents](https://github.com/win07xp/kaalm/blob/v2.2.0/guide/src/developers/framework-agents.md#level-1-gateway-only-zero-conversion).
